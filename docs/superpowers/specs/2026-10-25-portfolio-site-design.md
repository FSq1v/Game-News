# ゲーム＋AI ニュースサイト（ポートフォリオ版） 設計メモ

## 目的

- 今の Game News を、ゲームと AI のニュースを扱う、人に見せられるサイトにする。
- スマホで快適に読める。
- ポートフォリオに載せられる完成度にする（見た目・速さ・アクセシビリティ・README）。
- お金はかけない（GitHub Actions 公開リポジトリ枠 + Vercel Hobby）。今の URL（https://game-news-smoky.vercel.app/）は使い続ける。

## 決めたこと（2026-10-25 の相談）

| 項目 | 決定 |
|------|------|
| 作る場所 | Game-News リポジトリを拡張する。新しいリポジトリは作らない |
| AI ニュース | RSS の自動収集と、Obsidian で書いた「ニュースまとめ」の両方を載せる |
| まとめ記事の個人メモ | 「自分への影響：」で始まる行は、公開するときに取り除く。元のノートは変えない |
| 技術構成 | サイトは Astro に移す。収集は今の Python（`fetcher/`）のまま |
| 見た目 | 未 push の Apple 風リデザイン（`73517b7`〜`afd46b6`）の方向性を引き継ぐ。明るい配色を基本に、ダークモードにも対応する。そのコードは使わず、参考にするだけ |
| サイト名 | 「GAME FEED」から変える。候補は実装前に出して決める |

## 現状（2026-10-25 時点で確認したこと）

- 公開中のサイトは古いダークなダッシュボード版。手元の `main` は `origin/main` より 8 コミット進んでいて、1 コミット遅れている（遅れているのは bot の `Update news.json` だと思われるが、中身は未確認）。
- 手書きのまとめは `<保管庫>/30_ニュース/2026-10-14_ニュースまとめ.md` の 1 本だけ。プロパティは `created` `type` `period` `tags`。本文は `## AI` / `## ゲーム` の下に `### 見出し` ＋ 本文 ＋ `- 出典：サイト名（日付） URL` の箇条書きという形。

## ページ構成

| URL | 中身 |
|-----|------|
| `/` | 一番上に最新のまとめ記事を大きく 1 本。その下にゲームと AI の最新ニュースを数件ずつ並べ、それぞれ `/game` `/ai` へのリンクを置く。初めて来た人がどんなサイトかわかるように、短い説明を 1 行入れる |
| `/game` | ゲームニュースのフィード。フィルタ（すべて・国内・海外・公式・お気に入り）、検索。「ニュース」「セール」のタブ。セールの中に Epic の無料配布も入れる |
| `/ai` | AI ニュースのフィード。フィルタ（すべて・国内・海外・公式・お気に入り）、検索 |
| `/digest` | まとめ記事の一覧（新しい順）。日付、対象期間、タグ、見出しの数を出す |
| `/digest/YYYY-MM-DD` | まとめ記事のページ。目次、出典リンク、注記（「確認できなかった」など）を見やすく出す |
| `/about` | サイトの説明、仕組みの図、使った技術、情報の扱い方（出典の出し方、翻訳についての注意） |
| `/rss.xml` | まとめ記事の RSS 配信 |
| 404 | 独自の 404 ページ |

お気に入りは今と同じように `localStorage` に保存する（ブラウザごと）。ゲームと AI のお気に入りは共通にする。

## 構成とデータの流れ

```
[毎時17分・GitHub Actions]
  pytest
  → python -m fetcher        … ゲーム＋AI を集めて data/news.json を作る
  → data/news.json をコミット
  → npm ci && npm run build  … Astro が data/news.json と src/content/digest/ を読んで dist/ を作る
  → vercel deploy --prebuilt --prod

[まとめを書いたとき・自分の PC]
  py scripts/sync_digests.py
  → <保管庫>/30_ニュース/*.md を読み、公開用に変換して src/content/digest/ に書く
  → git diff で中身を確認してから commit / push（push の前に毎回確認を取る）
```

### ディレクトリ

```
fetcher/            収集（Python、今のまま。AI のソースを足す）
scripts/
  sync_digests.py   まとめの取り込み
data/news.json      収集結果（今の public/news.json から移す）
src/
  content/digest/   公開用に変換したまとめ記事（.md）
  content.config.ts digest コレクションのスキーマ
  pages/            上のページ構成のとおり
  components/       ヘッダー、ニュースカード、セールカード、フィード（island）など
  layouts/          共通のレイアウト（head、OGP、ヘッダー、フッター）
  styles/           色・文字・余白のトークン（CSS 変数）
public/             favicon、静的な画像
tests/              pytest（今のもの＋追加分）
```

### `news.json` の変更

- 各ニュースに `genre`（`"game"` または `"ai"`）を足す。それ以外の項目（`id` `title` `link` `summary` `source` `region` `platforms` `image` `published_at` `first_seen`）は今のまま。
- 置き場所を `public/news.json` から `data/news.json` に移す。ビルドのときに Astro が読み込むので、ブラウザから直接取りに行く必要がなくなる。
- 前回データとのマージ、24 時間まで前回データを出し続ける動きは今のまま。

### AI ニュースのソース

`fetcher/rss.py` の `FEEDS` に `genre` を足して、AI 系のソースを追加する。候補は次のとおり。RSS の URL が生きているか、どれくらいの頻度で更新されるかは実装のときに確認して、取れないものは外す（この設計の時点では未確認）。

| ソース | region |
|--------|--------|
| ITmedia AI+ | jp |
| Publickey | jp |
| OpenAI ニュース | official |
| Anthropic ニュース | official |
| Google AI ブログ | official |
| The Verge（AI） | global |
| TechCrunch（AI） | global |

海外記事のタイトルは今と同じように日本語に翻訳する。翻訳したタイトルには、原文があることがわかる印を付ける（`/about` にも翻訳について書く）。

### まとめの取り込み（`scripts/sync_digests.py`）

- 入力：`<保管庫>\30_ニュース\*.md`（場所はコマンドライン引数で変えられるようにする）
- 変換のルール：
  - 「自分への影響：」で始まる箇条書きの行を取り除く。
  - `[[ノート名]]` と `[[ノート名|表示名]]` は普通の文字（表示名）にする。保管庫の中の別ノートへのリンクは公開しない。
  - プロパティは `created` → `date`、`period`、`tags` を残し、`title` を本文の最初の `# ` から作る。`type` は落とす。
  - `- 出典：…` の行はそのまま残す（記事ページで見やすく整形する）。
- 出力：`src/content/digest/YYYY-MM-DD.md`。同じ日に `_2` が付いたノートがあるときは `YYYY-MM-DD-2.md`。
- 既に同じ名前の出力ファイルがあって、中身が変わるときは上書きする（元は Obsidian 側にあるので）。そのとき、何を書き換えたかを画面に出す。
- 取り除いた行の数を記事ごとに画面に出す。消しすぎや消し忘れに気づけるように。

## 見た目

- スマホ（幅 375px）から作る。899px 以下は 1 カラム、900px 以上は 2 カラム（フィード＋サイドの情報）。
- 色・文字・余白は CSS 変数で決めて、`prefers-color-scheme` でダークモードに切り替える。
- 文字は日本語向けにシステムフォントを中心にする（重い Web フォントは読み込まない）。
- 画像のないニュースは、ソース名を入れたプレースホルダーにする（今と同じ考え方で、見た目は作り直す）。
- 動きは控えめにする。`prefers-reduced-motion` のときは止める。

## 品質の基準（できたかどうかはこれで確かめる）

- Lighthouse のモバイル計測で Performance・Accessibility・Best Practices・SEO がすべて 90 以上（`/`、`/game`、`/digest/2026-10-14` の 3 ページで測る）。
- 幅 375px で横スクロールが出ない。タップできるところは 44px 以上。
- キーボードだけで、フィルタ・検索・タブ・お気に入りを操作できる。文字のコントラストは WCAG AA。
- ページごとに `title`、`description`、OGP（`og:title` `og:description` `og:image`）がある。まとめ記事は記事ごとに OGP 画像をビルドのときに作る。
- サイトマップを出す。
- JS はフィードのフィルタ・検索・お気に入りの部分だけ（Astro の island）。まとめ記事のページは JS なしで読める。
- 外から来た文字列（タイトル、要約、URL）は、必ずエスケープされた形で出す（`set:html` は使わない）。リンクは `http` / `https` だけ通す。

## テスト

- pytest：
  - AI ソースを足した `FEEDS` で、各項目に `genre` が付くこと。
  - マージ処理で `genre` が保たれること。
  - `sync_digests.py`：「自分への影響」の行が消えること、`[[ ]]` が普通の文字になること、プロパティの変換、`_2` の名前の扱い。テストには `tests/fixtures/` に置いた小さなノートを使い、本物の保管庫は読まない。
- Astro：`astro check`（型）と `astro build` が通ること。ビルドした `dist/` に対してリンク切れのチェック（サイト内のリンクだけ）。
- CI：上のテストを Actions の毎時の処理と、PR のときの両方で動かす。テストが失敗したら公開しない。

## エラーのときの動き

- あるソースの取得に失敗しても、ほかのソースは更新する（今のまま）。失敗したソースは最後に成功してから 24 時間まで前回のデータを出す。画面には「一部の取得に失敗」と小さく出す。
- `astro build` が失敗したら、デプロイしない。公開中のサイトはそのまま残る。
- `data/news.json` が壊れていたり、なかったりしたときも、ビルドは通してまとめ記事は出す。フィードには「ニュースを読み込めませんでした」と出す。
- まとめの取り込みで、プロパティの `created` がない・形がおかしいノートは飛ばして、画面に理由を出す。

- 未 push の 8 コミットを別に公開すること。このブランチは手元の `main` から切ったので 8 コミットを含んでいるが、`public/` の中身は Astro 版で置き換わる。`origin/main` の 1 コミット（bot の更新と思われる）は、PR を出す前に取り込む。
